# 芽纪移动端原型 UX 体验报告

**日期**：2026-08-08  
**原型**：`apps/mobile`（Expo Web）  
**运行环境**：`http://localhost:8082`（8081 同时占用但超时；本轮以 8082 为准）  
**走查方式**：390×844 手机视口真实点按（Playwright Chromium；cursor-ide-browser MCP 本轮不可用）。截图目录：`docs/ux-screenshots-2026-08-08/`  
**权威边界**：家庭孕育档案工具；非社区、非互联网医院、非诊断。AI 仅解释 + 档案事实提示。

---

## 1. 体验身份与场景设定

我以双重身份走完主路径：

1. **极度挑剔的互联网产品经理**：看过美柚/宝宝树/孕育类工具/备忘录式记录/「拍报告问 AI」产品无数遍，对信息架构、重复入口、标题层级、信任文案、视觉廉价感零容忍。
2. **已怀孕约 4 个月的宝妈**：今天对应示范档案约 **孕 24+3 周**。刚做完孕中期超声，口袋里有纸质/手机相册报告；脑子里装着「胎盘 II 级是不是坏事」「血常规还要不要复查」「下个月大排畸带什么」。累、怕漏、讨厌被吓、也讨厌冷冰冰的表格。

核心心理任务只有五句：

- 把报告收进家里  
- 看懂这张纸在说什么  
- 知道下一步做什么  
- 数字有没有在变  
- 这份档案能不能放心给另一半看、敢不敢继续塞隐私

## 2. 总体结论

**一句话**：芽纪已经摸到「温暖家庭档案」的正确气质——不像社区、不像医院 App——但「健康连成线」与「诊后收进来」两条主线仍有完成度落差；报告确认页信息过重，健康页承诺了趋势却只给了色块快照。

| 维度 | 评分 (1–10) | 点评 |
| --- | ---: | --- |
| 美感 | **7.5** | 马卡龙奶油底 + 叶芽 Logo 有辨识度；底栏 Unicode 图标拉低成色 |
| 清晰度 | **6.5** | IA 方向对；「此刻」下一步偏挤，健康页文案与现实不符 |
| 信任 | **8.0** | 隐私三底线、OCR 先确认、免责声明到位；比多数孕育 App 克制 |
| 情绪价值 | **8.0** | 「还没有故事」「大约还有 16 周陪伴」像家人；偶有说明书腔 |
| 完成任务效率 | **6.0** | 收报告主链可走通，但确认页过长；健康趋势未兑现；Web 层叠点击偶发失效 |

**信息架构核查（本轮）**：底部 Tab 为 **此刻 / 档案 / 健康 / 我的**；**未出现独立「添加」Tab**。添加入口在 **档案 →「收进来」**，符合预期，**无需回修入口**。

## 3. 首屏与信息架构

### 3.1 登录 / 示范入口

截图：`01-login.png`、`02-login-demo-expanded.png`

- 叶芽 Logo +「家庭孕育档案」+ 标语「把每一次看诊，收成家里能翻开的故事」——品牌信号足够强，不像又一个「孕妈工具箱」。
- 「体验示范档案」折叠存在：对种子用户友好，但首屏偏空，下半屏浪费；演示入口略像工程后门，不像产品邀请。
- 协议用 Switch 而非可点链接勾选，略「原型感」，但至少没有一登录就恐吓。

### 3.2 「此刻」首屏

截图：`03-now-top.png`、`04-now-scrolled.png`

**做得好的：**

- Hero 数字「24 周 +3 天」一眼可读；「小芽正在慢慢长开」「大约还有 16 周陪伴」有温度，不像周数计算器。
- 「下一步」抓住诊后焦虑；未闭环血常规写明「档案中未见记录」——这是档案产品该干的事。
- 「成长痕迹」色块（胎心/体重/血压）与健康模块语言一致。
- 参考日程脚注「以医生安排为准」边界正确。

**刺眼之处：**

- 首屏同时塞：孕周卡 + 3 条下一步 + 成长痕迹 + 携带清单 + 最近就诊 → **孕妈下班刷手机时偏满**，像「今日待办 Dashboard」，不像「此刻一张安静的明信片」。
- 「设提醒 / 完成」并列，语义层级接近，容易误触「完成」把还没做的事划掉。
- 底栏图标为 `● ☰ ♡ ◌`，与顶部精心叶芽形成割裂——**上半身高级，下半身草稿**。

### 3.3 「档案」与添加入口

截图：`05-archive-list.png`、`08-add-menu.png`、`08b-add-more.png`、`23-archive-empty.png`

- 「收进来」右上角薄荷绿按钮，文案比「添加/上传」更产品化；空态「还没有故事」+「点上方收进来就好」闭环清楚。
- 添加菜单「刚看完医生？三件事就够」——收报告 / 录医嘱 / 记一条，结构克制，值得保留。
- **风险**：添加只挂在档案顶栏，拇指热区偏远；「此刻」是情绪首页，却没有「收进来」轻入口。第一次用户若停在「此刻」发呆，可能找不到归档动作（空态文案只在档案页自救）。
- 列表把体重/血压标成「其他」，类型感弱，像备忘录混进病历本。

### 3.4 阶段小结

截图：`06-stage-summary-entry.png`、`07-stage-summary-generated.png`、`07b-stage-summary-full.png`

- 简版小结语气对：汇总事实 +「以医生意见为准」，没有诊断腔。
- 完整分区（时间线 / 指标变化 / 医院结论）是档案产品该有的「给家人讲清楚」。
- **「重新生成」按钮过大过重**，像运营后台；家人来看小结，不该先看见「再跑一遍模型」。

## 4. 核心任务路径走查

### 4.1 归档报告（上传 → 识别 → 确认）

截图：`09-report-upload.png` → `10-report-processing-or-review.png` → `11/12/13-report-review-*.png`

**路径**：档案 → 收进来 → 收报告 →（自动/手动）识别 → 确认报告。

**亮点：**

- 处理中文案「结果会先给你确认，不会自动写入档案」——信任感满分动作。
- 指标色块摘要 +「待核对」低置信徽章 +「同步为健康记录」开关：产品边界（OCR 助手、用户确认）被做进 UI。
- 「白话解读」里对「胎盘 II 级」的解释克制、有引用感，**正是孕妈会截图发给家人的段落**。
- 「建议下一步」限定提醒/携带/记叮嘱，没有滑向问诊。

**问题：**

1. **确认页过长**：字段逐条 + 每条同步开关 + 白话解读 + 建议 + 携带开关 + 免责 + 主按钮。诊后疲惫状态下，扫完像填税表。
2. **白话解读位置偏下**：孕妈最先想看的是「这是啥意思」，却先被测量字段淹没。
3. **走查中「确认归档」曾出现点击后无离开页面的卡顿**（Web 原型复现：`14-report-confirmed.png` 仍停在确认页）。根因偏向 `confirmReport()` 返回值时序 + 仅在有 `eventId` 时 `goReplace`。**本轮已顺手加固**（确认后始终回「此刻」；`eventId` 预先生成）。需在真机再验一次。
4. Expo Web 多层绝对定位叠层会导致列表点击被拦截（走查日志可见 pointer intercept）——原型演示稳定性 P1。

### 4.2 看懂结果

- 白话解读质量方向正确；引用「报告原文 P1」增强可核查感。
- 事件详情（`25-event-detail.png`）偏薄：标题 + 指标条 + 删除，**缺少「回到白话解读/原报告」的二次阅读入口**。归档后「看懂」能力断在确认页。

### 4.3 知道下一步

- 「此刻 · 下一步」与报告「建议下一步」形成呼应，产品故事完整。
- 参考日程与真实预约混排：糖耐「设提醒」vs 大排畸「完成」——规则需更显式，否则像两个产品拼在一页。
- 阶段小结里点出未闭环复查，是「档案智能」该有的价值，不是惊吓式风险预测。

### 4.4 看趋势（健康）

截图：`17-health.png`、`18-health-fetus.png`、`19-health-detail.png`

- 文案「报告里的数字，会在这里慢慢连成线」定调极好。
- **现实：妈妈页只有体重/血压两张色块；胎儿页有胎心/双顶径；点进详情是列表，不是线。**  
  对挑剔 PM：这是 **文案超售**。对孕妈：我想看胎心 162→146 的安心感，结果还要自己脑补。
- 与「此刻 · 成长痕迹」信息重复，却没有在健康页给出更强的时间维度回报——重复入口的收益不足。

### 4.5 家庭信任

截图：`20-me.png`、`21-trust.png`、`26-family.png`

- 「这份档案，只属于你们一家」+ 隐私三底线（加密 / 不训练 / 可导出可删）——**这是芽纪相对社区型孕育 App 的核心差异化表达**，请保护。
- 家庭成员「夫妻共用一份档案，权限从简」符合 MVP；「邀请另一半」存在。
- 导出/删除目前是 Alert 模拟，可以，但信任页若只有承诺没有「上次导出时间/数据范围」会略虚。

### 4.6 录医嘱 / 记一条（点开体验）

截图：`15-voice-recording.png`、`15b-voice-review.png`、`16-quick-note.png`

- 录音页极简、隐私一句到位、大按钮「结束」适合诊室单手。
- 转录核对页抽取结果有价值，但 **铁剂相关条目重复**（处方继续 / 按处方剂量），像模型没去重。
- 「记一条」三分法（叮嘱/用药/监测）清楚，但页面对空过大，保存按钮发灰时缺少「差一句就能存」的引导温度。

## 5. 视觉与气质

| 观察点 | 判断 |
| --- | --- |
| 马卡龙配色 | **成立**：奶油雾底 `#FDF7F2`、薄荷绿、蜜桃、指标色块分层清楚，不像冷工具 |
| 叶芽 Logo | **有记忆点**；登录与「我的」使用充分；「此刻」右上角小标可爱 |
| 是否像母婴运营 App | **不像**。无社区瀑布、无电商货架、无恐吓式科普 Banner——克制是优势 |
| 是否像冷工具 | 大部分不像；健康页空白 + 底栏草稿图标会短暂掉回「未完工工具」 |
| 标题重复 | 栈标题「确认报告」与正文报告名并存尚可；添加页标题「添加」与 lead「三件事就够」不打架 |
| 遮挡 | 顶角 glow 大圆与标题轻微抢戏（空态更明显）；Web 叠层拦截点击属工程问题 |

总体气质：**「家里的暖色档案本」**，不是「医院 LIS 皮肤」也不是「美柚首页」。请守住，不要为了热闹加运营模块。

## 6. 文案与情绪价值

**像家人的句子（请保留）：**

- 把每一次看诊，收成家里能翻开的故事  
- 小芽正在慢慢长开 / 大约还有 16 周陪伴  
- 还没有故事  
- 刚看完医生？三件事就够  
- 写进产品的三条底线，不是营销话术  
- 报告里的数字，会在这里慢慢连成线  

**仍偏说明书/工程的地方：**

- 「同步为健康记录」× N：正确但冷，可收成「一并记入健康趋势（可关）」总开关  
- 「抽取结果」「JSON + 附件」：信任页技术透明 OK，记一条/录音页可更白话  
- 「其他」作为事件类型：没有情绪，也没有信息  

情绪价值总分不低，但 **健康页「连成线」未兑现** 会伤害信任——温暖文案一旦跳票，比冷文案更伤。

## 8. 亮点（值得保留）

1. **产品边界感强**：无社区、无问诊入口、AI 解释带引用与免责——和「拍报告问 AI」竞品拉开。  
2. **「收进来」语言系统**：比「上传/添加」更符合家庭档案心智。  
3. **添加菜单三刀流**：收报告 / 录医嘱 / 记一条，诊后场景清晰。  
4. **OCR 先确认再入档**：处理中文案直接说「不会自动写入」。  
5. **白话解读克制**：胎盘分级解释不做诊断。  
6. **隐私与信任页**：三条底线有产品立场，不是法律附录。  
7. **叶芽 + 马卡龙**：有机会形成可识别品牌，而不是又一个薄荷绿医疗模板。  
8. **未闭环复查**出现在下一步：档案产品的「记性」，不是恐吓。

## 9. 竞品体感对比（口头对标）

| 类型 | 体感 | 芽纪应落点 |
| --- | --- | --- |
| 美柚 / 宝宝树式社区感 | 热闹、内容流、焦虑与广告并存 | **明确远离**。当前原型已做到「安静」，请勿回潮 |
| 拍报告问 AI | 快、爽、解释强，但易飘成轻问诊，档案沉淀弱 | **借解释能力，拒问诊人格**；解释必须可回档案、可引用 |
| 备忘录式记录 | 快记、乱、难趋势、难家人共用 | **结构上要赢它**：同一时间轴 + 健康投影；记一条只是支线 |
| 医院/体检 App | 冷、账户绑定、看不懂、不敢给家人 | **温度与家庭权限上要赢它** |

**芽纪正确坐标**：  
**「可共享的家庭孕育档案本」** = 备忘录的快 × AI 解释的懂 × 医院报告的真 × 社区的反面（安静）。  
不要去做第四个美柚，也不要去做第二个「报告 GPT」。

## 10. 给下一轮原型的优先改动（最多 7 条）

按影响力排序：

1. **兑现「连成线」**：健康详情至少给胎心/体重/关键产检指标的简易趋势（可用同轴时间点），删掉或改写做不到的承诺句。  
2. **重排报告确认页**：上半屏 = 白话解读（最多 3 条）+ 关键指标；字段核对折叠；「同步健康」改总开关；主按钮吸底且确认反馈明确。  
3. **降噪「此刻」**：下一步默认 1～2 条，其余进「更多」；区分「参考日程」与「已预约/未闭环」视觉层级；完成操作二次确认。  
4. **补齐品牌底栏图标**：用叶芽体系的线性图标替换 `●☰♡◌`，立刻提升「成品感」。  
5. **添加可发现性**：保持「不设添加 Tab」，但在「此刻」提供一条轻文案入口（如「看完医生了？收进来」），空态与有数据态都可见。  
6. **阶段小结默认家人简版**：「重新生成」降为次级；完整分区作为展开，而不是生成后还要再点一次才像完整产品。  
7. **归档后可读性**：事件详情增加「白话解读 / 原字段」回看；录音抽取去重；事件类型去掉空洞的「其他」。
