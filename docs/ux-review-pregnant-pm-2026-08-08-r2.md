# 芽纪移动端原型 UX 体验报告（第二轮）

**日期**：2026-08-08（第二轮深度走查）  
**对照**：第一轮报告 `docs/ux-review-pregnant-pm-2026-08-08.md`  
**原型**：`apps/mobile`（Expo Web · `http://localhost:8082`）  
**走查方式**：390 逻辑宽真实点按（cursor-ide-browser）；截图：`docs/ux-screenshots-2026-08-08-r2/`（若目录同步延迟，亦可对照临时截图 `r2-*.png`）  
**权威边界**：家庭孕育档案；非社区 / 非互联网医院 / 非诊断。AI 仅解释 + 档案事实提示。

---

## 1. 体验身份与场景设定

双重身份不变：

1. **极度挑剔的互联网产品经理**：崇尚简洁优雅，对重复入口、标题层级混乱、文案语义撞车、廉价图标、Dashboard 化零容忍。用过美柚/宝宝树式社区、备忘录式记录、「拍报告丢给大模型」无数遍——知道「温暖」很容易做成「母婴运营」，「专业」很容易做成「冷仪器」。
2. **已怀孕约 4 个月的宝妈**：示范档案约 **孕 24+3 周**。刚做完孕中期超声，最怕「胎盘 II 级」四个字；最烦打开 App 还要滚动半屏才能看见「下一步」；一只手抱着袋子、另一只手拇指够不到右上角。

本轮重点验证：上一轮提出的折叠降噪、健康趋势、白话优先、底栏图标、档案「收进来」是否**真的让产品更安静**。

---

## 2. 总体结论

**一句话**：第二轮明显从「正确气质的半成品」推进到「可被认真评价的产品雏形」——「此刻」首屏终于像一张明信片而不再是待办墙；报告确认页把「看懂」放在「核对」之前。但折叠若只是把杂物塞进「更多」，档案顶栏仍四层导航，健康页的「连成线」仍像装饰性小柱，挑剔的我会说：**安静了一半，优雅还欠收口。**

| 维度 | 上轮 | 本轮 | 点评 |
| --- | ---: | ---: | --- |
| 美感 | 7.5 | **8.0** | 叶芽 + 马卡龙 + 几何底栏统一了；Web 宽屏登录仍像内容贴左的草稿 |
| 清晰度 | 6.5 | **7.5** | 「此刻」折叠有效；档案顶栏与「收进来」语义仍抢戏 |
| 信任 | 8.0 | **8.0** | 边界文案稳定；未见越界诊断 |
| 情绪价值 | 8.0 | **8.0** | 温暖文案仍在；「更多」太工程化，略降温 |
| 完成任务效率 | 6.0 | **7.5** | 收报告主链更顺；白话优先缩短决策路径 |

**IA 核查**：底栏仍为 **此刻 / 档案 / 健康 / 我的**，无独立添加 Tab。添加 = 档案「收进来」+ 此刻轻文字链 → `/add-menu`。符合当前产品决策。

## 4. 首屏与信息架构

### 4.1 登录

截图：`r2-01-login.png`

**保留**：叶芽字标、奶油雾底、标语「把每一次看诊，收成家里能翻开的故事」——品牌测试通过：去掉导航也知道是芽纪。  
**挑剔**：

- Expo Web 宽屏下，表单与品牌**贴左上角一簇**，右侧大片空白——像没做自适应的组件堆，不是「留白的高级」。
- 「体验示范档案」存在合理，但协议 Switch + 禁用「继续」仍偏原型实验室。
- 作为宝妈：我不会在登录页读完标语就感动到填真手机号；示范入口应更像「先看一眼样例家庭」，而不是工程后门。

### 4.2 「此刻」（本轮焦点）

截图：`r2-03-now-demo.png`

**首屏默认结构（好）**：

1. 日期 + 叶芽  
2. 孕周大卡（24 周 +3 天 + 阶段句）+「展开细节」  
3. 下一步（默认 2 条）+「更多 1 条」  
4. 轻链「看完医生了？收进来」  
5. 折叠条「更多｜摘要｜展开」

这比上轮「一屏五段」克制得多。作为孕妈，我终于能在一屏内看见「我现在几周」和「下一件要紧事」。

**仍刺眼**：

1. **下一步副文案过长**  
   「9 月 15 日 · 已预约 · 携带既往超声与医保卡」一行塞三种信息；「6 月 3 日报告建议两周后复查，档案中未见记录」像病历摘要。建议：标题一行 + 副文案最多「日期 · 状态」，携带/原因点进详情。
2. **「完成」按钮过于醒目**  
   薄荷绿块与「设提醒」层级接近时，误触风险仍在（上轮提过，二次确认有帮助但未在 Web 走查中验证 Alert）。
3. **文案语义撞车：「收进来」**  
   产品语义 = 归档/导入；中文日常还可理解为「把摊开的收起来」。与折叠「收起」并置时，挑剔 PM 会皱眉。建议改为「收下报告」或「去归档」。
4. **「更多」作为垃圾桶命名偏工程**  
   摘要很好，标题可改为「痕迹与携带」之类可读名称，而不是程序员的 More。
5. **折叠交互文案过多**  
   同屏出现：展开细节 / 更多 1 条 / 收进来 / 展开——四个「开合」动词，认知税高。应统一一套手势语言（例如一律右侧「展开/收起」chevron）。

### 4.3 「档案」

截图：`r2-07-archive-list.png`（有数据）；空态见走查中「还没有故事」

**好的**：

- 列表去掉色块墙，只留「胎心 146次/分 · 等 7 项」一行——呼吸感回来了。  
- 「筛选」默认收起，摘要显示「全部」。  
- 「收进来」仍在右上，添加菜单三入口干净（`r2-09-add-menu.png`）。

**仍刺眼**：

1. **顶栏四层**：家庭名 + 收进来 / 阶段小结条 / 筛选条 / 列表——有内容时，拇指要划过三道「管理条」才到故事。阶段小结可沉为列表首卡或「更多」内。  
2. **时间序把居家监测顶在超声之上**  
   作为孕妈，我打开档案想先看见「那张让我慌的超声」，却先看到今天早上的血压/体重。建议：默认「就医与报告」优先，或监测合并为一条「今日监测」。  
3. **空态友好，但全页刷新会丢示范状态**  
   Web 直接打开 `/timeline` 会回到「还没有故事」（内存态丢失）。原型可接受，但演示路径必须强调「用底栏切换、勿刷新」。

### 4.4 「健康」

截图：`r2-08-health.png`

- 文案「报告里的数字，会在这里慢慢连成线」承诺感强。  
- 妈妈分段出现体重/血压色块 + 底部小柱——**比上轮空口白话好**。  
- 挑剔点：柱状更像装饰，不像「连成线」；胎儿指标在另一 Chip，孕妈默认停在「妈妈」时看不到胎心——**情绪主指标藏了一层**。建议孕期默认「胎儿」或首屏同时露出胎心。  
- 下半屏大片留白：不是高级，是「内容不够」。

### 4.5 添加菜单 / 报告确认

截图：`r2-09-add-menu.png`、`r2-10-report-review.png`

**添加**：三卡马卡龙分区 +「刚看完医生？三件事就够」——本轮最佳单页之一，几乎可直接进可用性测试。

**确认报告**：

- 白话解读置顶，「胎盘 II 级」安抚句仍在——宝妈核心焦虑被接住。  
- 关键指标色块一眼可读。  
- 字段整段折叠「核对全部字段（6）」——正确。  
- 建议下一步 + 免责 +「确认归档」链路完整。  
- 仍偏长：白话三条 + 指标 + 建议三块，一屏装不下；可考虑白话默认展开前 2 条、「再看一条」。

## 6. 视觉与气质

- **做对了**：奶油雾底、薄荷绿/蜜桃、叶芽 Logo、几何 Tab——上下身终于同一件衣服。  
- **危险**：全页柔光 blob + 多卡片圆角，再多一层就容易滑向「母婴运营皮肤」。继续克制插画与贴纸。  
- **Web 演示债**：宽屏登录布局不合格；手机视口下气质成立。对外演示必须锁 390 宽。

## 8. 可用性问题清单

### P0

1. **「收进来」与折叠「收起」语义混淆**  
   复现：打开「此刻」，同屏见「收进来」与「展开/收起」。  
   建议：归档入口改为「收下报告」/「去归档」。

2. **健康页孕期默认看不到胎心**  
   复现：健康默认「妈妈」，仅体重/血压。  
   建议：孕期默认「胎儿」或首屏同时展示胎心。

### P1

3. **「此刻」下一步副文案过载**——压缩为日期·状态。  
4. **档案顶栏管理条过多**——阶段小结降级。  
5. **档案时间序：监测压过关键报告**——就医/报告优先或监测聚合。  
6. **折叠动词不统一**——统一为 chevron +「展开/收起」。  
7. **健康 sparkline 装饰感**——改为真折线或标注起止值/趋势词（「近三次平稳」）。  
8. **登录宽屏布局崩坏**——居中或限宽卡片。

### P2

9. 「更多」命名工程化。  
10. 报告确认页仍偏长，白话可再折叠。  
11. Web 全页刷新丢失内存态——演示说明或加 persist。  
12. 「完成」视觉权重仍偏高。

## 10. 竞品体感坐标（更新）

```
社区运营感 ←——————●——→ 家庭档案工具
冷仪器表格 ←————●————→ 有温度的陪伴
拍了就问 AI ←——●——————→ 先归档再看懂
```

相对上轮：向「家庭档案工具 / 有温度」又挪了半格。尚未到「我愿意把整袋报告都交给它」——卡在健康趋势可信度与档案叙事优先级。

---

## 11. 给下一轮的优先改动（最多 7 条）

1. **改名「收进来」** → 「收下报告」或「去归档」，消除与折叠语义冲突。  
2. **压缩「下一步」副文案**；携带说明进详情。  
3. **孕期健康默认露出胎心**（默认分段或双露出）。  
4. **健康趋势从「装饰柱」升级为可读趋势**（折线或「↑/→/↓ + 起止」）。  
5. **档案顶栏减层**：阶段小结勿与筛选并列抢首屏。  
6. **档案列表叙事**：报告/产检优先于碎监测，或监测合并。  
7. **统一折叠交互语言**（chevron + 展开/收起），「更多」改产品名。

---

## 12. 结尾（宝妈 + PM 各一句）

**宝妈**：你们终于肯让我先看见「我在第几周」和「下一件要紧事」了；别再让我在「妈妈」页里找不到胎心。  
**PM**：折叠是正确的结构手段，不是把杂物扫进「更多」就叫优雅——命名、默认视图、列表优先级，才是下一刀该切的地方。
