# 芽纪 · 产品定位（访谈收敛版）

> 文档版本：2026-08-08 v3（基于三轮共 38 问的种子用户深度访谈收敛）  
> 状态：产品定义已确认，作为大步骤一冻结基线  
> 覆盖范围：备孕（归档）· 孕期 · 妈妈产后恢复 · 宝宝 0–1 岁

---

## 1. 产品从哪里来

芽纪源于一个正在经历孕育的真实家庭：

- 从备孕开始就在跑医院，检查报告攒了满满一大袋，纸质电子混存  
- 开车一小时、排队半天，见医生只有两三分钟；遇到没耐心的医生，出了诊室就不知道下一步做什么  
- 迫不得已背对医生开录音，录完存在手机里再没听过  
- 拿到报告第一动作是发给 AI 解读——图文发一家、音频发另一家，每家 AI 都只有片面信息，每次都要重新交代背景，还要负担会员和网络成本  
- 病历上一个"先兆流产"的通用写法，让全家吓了一跳，事后才知道虚惊一场  
- 下次检查的时间靠护士口头说、靠宝妈群通知，忙起来就怕漏  
- 换医院、去社区医院做检查时，全部历史只存在自己手上

处在同样阶段的宝爸宝妈很多，困惑是一样的：**不知道如何整理检查报告、病历和医生的各种叮嘱，更没法把几个月的信息串成有用的结论。**

## 2. 一句话定位

**芽纪是属于一个家庭的孕育档案与解读助手。**

从备孕到宝宝一岁，你们把每次检查的报告、医生说的话（录音）、在家测的数据交给它；它记得完整的历史，用白话告诉你们：**发生了什么、这个词是什么意思（引用官方指南出处）、下一个标准节点是什么、下次去医院要带什么。**

它不给诊疗建议、不评判医生——它让你们**带着完整的事实去见医生**。

## 3. 它替代的是什么

不是市面上装了不用的孕期 App，而是用户现在的手工流水线：

```text
通用 AI（图文）+ 另一家 AI（音频）+ 多家交叉验证
+ 每次重新交代背景 + 会员与网络成本 + 信息碎在各个工具里
```

芽纪 = **一个懂孕育的、拥有你全部上下文的、开箱即用的档案助手**。差异点不是"有没有 AI"，而是：

1. 它记得完整历史，不用每次复述背景  
2. 报告、录音、居家数据、费用在同一个地方  
3. 解读完自动归档成轨迹，而不是散落在聊天记录里  
4. 解读标注官方指南出处，答得准且可查证

## 4. 用户与使用形态

- **夫妻二人共用一份家庭档案**。常见分工：一方是"信息管理员"（录入、整理、先看解读），另一方随时查看；不需要每次转述。  
- **老人不进产品**。用「阶段小结」生成的简化结论口头转述即可，不做老人端和复杂权限。  
- 孕育是家庭共同参与的事，产品强调**家庭与宝宝**的概念，而非个人工具。

## 5. 五个核心场景

| 场景 | 产品动作 |
|---|---|
| **S0 第一次使用** | 极简建档（阶段 + 一个日期）+ **10 分钟批量导入**存量报告：连拍/多选 → 批量识别 → 先粗归档，细节以后慢慢补 |
| **S1 诊室里** | 一键就诊录音（打开 App 一个大按钮，减少尴尬）、随手拍报告 |
| **S2 出诊后 30 分钟** | 录音自动转写并抽出医嘱 / 用药 / 下次检查；报告 OCR + 白话解读（标官方出处）；恐慌时刻拍病历页，秒级解释术语 |
| **S3 平时** | 「此刻」页：当前节点 + 下一步（内置标准产检时刻表、疫苗计划、产后 42 天等节点，官方来源）+ 节点材料清单（含建档证件等非医疗材料）；居家监测快速记录（体重、血压、胎心） |
| **S4 阶段回顾与下次就诊** | 阶段小结（跨报告事实汇总，也可转述给老人）；下次就诊携带清单；换医院或被推销检查时，拿出主治医嘱当场对照 |

## 6. AI 边界（种子用户亲自划定，与合规红线重合）

四层能力，只做前两层：

| 层 | 内容 | 做不做 |
|---|---|---|
| ① 解释 | 报告、病历、术语白话化（"先兆流产是病历通用写法"），标注官方指南出处 | **做** |
| ② 事实提示 | 基于完整档案：指标连续变化、报告建议的复查未闭环、同类检查已做过几次、标准节点将至 | **做** |
| ③ 行动建议 | 该补什么、该不该做某检查、该吃什么药 | **不做** |
| ④ 评判医生 | 判断医生对错、是否过度医疗 | **不做** |

用户原话："这玩意不可能比医生还牛逼，那就有点虚假了。"

补充规则：

- AI 结果确认前不进正式档案；固定免责文案 `AI 整理仅供记录理解，请以原始报告和医生意见为准`  
- 阶段小结只汇总事实、只引用原文，不产生新医学结论  
- 就诊录音仅存入用户自己的档案，绝不外传；录音入口提示"请遵守就诊场所相关规定"

## 7. MVP 范围

### 必须覆盖

- 极简建档：备孕 / 怀孕中 / 宝宝已出生，三阶段（备孕仅归档，无引导流程）  
- **批量存量导入**（S0 首次体验的成败点）  
- 报告 OCR 归档 + AI 白话解读（标官方出处）+ 建议下一步（提醒/携带，采纳后生效）  
- **就诊录音 → 转写 → 抽取医嘱 / 用药 / 下次检查**（确认后入档）  
- 医生叮嘱与用药的快速手动记录  
- 「此刻」驾驶舱：节点 / 下一步 / 携带清单 / 轨迹一瞥  
- **内置标准日历**：孕期产检时刻表、0–1 岁疫苗计划、产后 42 天复查等节点 + 节点材料清单（官方来源，标注"参考日程，以医生安排为准"）  
- 阶段小结（跨报告事实汇总）  
- 健康轨迹：妈妈孕期/产后指标、居家监测（体重/血压/胎心）、宝宝成长/体检/疫苗  
- 一次性提醒（并入「此刻」）  
- 每次就诊的轻量费用记录（金额 + 日期）  
- 夫妻共享（邀请成员，可查看/可编辑二选一）  
- 隐私：导出、删除、分项同意

### 收敛项

| 项 | 处理 |
|---|---|
| 家庭权限 | 夫妻共享即可；角色矩阵、审计日志、老人端不做 |
| 备孕阶段 | 只做归档（存报告、可解读、进时间轴），不做试管/备孕流程引导 |
| 全文搜索 | 时间轴筛选优先，搜索基础实现 |
| 挂号/排队/缴费 | 不做，用户已有医院小程序习惯 |

### P1（不阻塞 MVP）

- 一页纸就诊摘要（近期指标、在用药、上次医嘱，给医生看）  
- 档案自然语言查询、远程推送与重复提醒  
- 生长百分位曲线、PDF 导出排版  
- 发票/报销深度管理（MVP 只记金额日期）  
- 完整家庭角色矩阵与审计日志  
- 弱网续传 / 离线草稿

### 明确不做

- 行动建议、评判医生、诊断、风险预测、开放式医疗问答  
- 社区、资讯推送、广告、打卡催办、运营通知轰炸  
- 医生端、医院对接、挂号缴费  
- 喂奶、睡眠、排泄等高频生活记录  
- 老人端与多级权限

## 8. 信任承诺（写进产品的明文条款）

种子用户的三条"不满足就不用"底线：

1. **数据加密存储**，敏感信息不进日志与公开链接  
2. **绝不用于模型训练**  
3. **随时完整导出，删除即删除**；即使服务终止，用户可带走全部数据

信任感来源：解读标注官方指南出处 + 用起来"答得准"。底层使用强模型，不自训医疗小模型。

## 9. 产品气质与商业倾向

- 独立 App（非小程序）；简洁、优雅、强大；界面好看、操作高效（苹果风方向不变，见 [design-system.md](./design-system.md)）  
- 录入必须极轻：拍照归档、记叮嘱按 30 秒内完成设计；存量导入按 10 分钟内完成设计  
- 商业倾向：**买断制**优先于订阅（记录为倾向，不影响 MVP 开发）

## 10. 长期愿景（不影响 MVP 验收）

宝宝满一岁不是终点：持续记录孩子的健康检查，长成一份**有价值、有情感、能产生回忆**的家庭健康档案。MVP 验收线仍是备孕—孕期—产后—宝宝一岁，但数据结构不设天花板。

技术选型补充（已写入规格）：

- 智能能力通过 `OcrProvider` / `LlmProvider` / `AsrProvider` 三个可替换接口接入，首版使用**境内模型 API**，健康数据不出境
- 白话解读与标准日历的出处来自**自建可控知识库**（`fixtures/knowledge/`），禁止模型自由生成指南出处
- 模型结果一律落库缓存，配日成本上限与降级策略
