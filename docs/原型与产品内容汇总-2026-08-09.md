## 2. 产品定位与不可改变边界

### 2.1 一句话

芽纪是**属于一个家庭的孕育档案与解读助手**，覆盖备孕、孕期、妈妈产后恢复和宝宝 0–1 岁。

用户把检查报告、医生说的话（录音）、在家测的数据交给它；它记得完整历史，用白话说明：发生了什么、这个词是什么意思、下一个标准节点是什么、下次去医院带什么。  
**不给诊疗建议、不评判医生**——让用户带着完整事实去见医生。

### 2.2 不可改变的边界（本版与规格一致）

| 做 | 不做 |
|---|---|
| 家庭孕育档案；时间轴 /「此刻」为主线 | 母婴社区、资讯流、电商、广告、打卡催办 |
| 孕期 · 产后 · 宝宝 0–1；备孕仅归档 | 试管/备孕流程引导、老人端 |
| OCR / 帮读 / 录音转写 → **用户确认后**进档案 | 医疗诊断、风险预测、开放式健康问答 |
| 健康 = 同一份档案的趋势视图 | 第二套重复数据、强制重复录入 |
| 合规报告均可归档；未知类型走通用补录 | 提示「不支持某种报告」而阻断 |
| 提醒写入系统日历（真机） | 医生端、医院对接、挂号缴费 |
| — | 喂奶 / 挤奶 / 睡眠 / 排泄 / 尿布等高频生活记录 |

AI 四层模型（规格 §6.1）：只做①术语与报告解释、②档案事实提示；不做③行动建议（该补什么、该不该做检查、用什么药）、④医生评判。

## 3. 信息架构

### 3.1 底栏四 Tab（无独立「添加」Tab / FAB）

| Tab | 路由 | 职责 |
|---|---|---|
| 此刻 | `(tabs)/now` | 默认首页：当前节点、下一步、携带与痕迹（折叠） |
| 档案 | `(tabs)/timeline` | 事件时间轴；顶栏「收下报告」 |
| 健康 | `(tabs)/health` | 同源指标趋势；孕期默认「胎儿」 |
| 我的 | `(tabs)/me` | 档案完善、家庭、隐私与信任、隐藏演示 |

`add`、`reminders` 路由仍存在但 `href: null`，不出现在底栏。

### 3.2 添加入口

```text
档案顶栏「收下报告」  ──┐
此刻轻链「看完医生了？收下报告，芽纪帮读」──┼──→ /add-menu
                                        │
add-menu 三入口：收报告 · 录医嘱 · 记一条
「更多」：批量导入旧报告 · 设提醒（系统日历）
```

## 4. 核心用户旅程（可演示路径）

推荐演示（与 `docs/prototype-review.md` 一致，措辞以当前 UI 为准）：

1. **进入示范**  
   登录页展开「体验示范档案」→ **孕期示范**（或「已出生示范」）→ 直接进入「此刻」。  
   （登录表单可用「填入演示号」填入虚构号与验证码，走建档；演示号非真实手机号。）

2. **看懂当下**  
   「此刻」：孕周大数字、下一步（默认约 2 条，其余折叠）、痕迹与携带折叠区。

3. **收下报告**  
   档案「收下报告」或此刻轻链 → add-menu「收报告」→ 上传 / 处理中（Mock）→ **报告确认**：白话解读 → 关键指标 → 字段核对（折叠）→ 建议下一步（采纳）→ **确认归档** → 成功页回「此刻」。

4. **提醒与日历**  
   下一步「设提醒」或 add-menu「设提醒」→ `/reminder/new`；真机可写系统日历，Web 诚实降级。

5. **健康趋势**  
   「健康」看胎心 / 体重等与档案同源的点与轻量折线；点指标可看历史。

6. **阶段小结（原型）**  
   档案折叠「筛选与小结」→ 阶段小结 → 选时间范围 → 生成家人简版 / 完整分区。

7. **录医嘱 / 批量导入（原型深度）**  
   add-menu「录医嘱」「更多 → 批量导入」可点通 Mock 流程；完整 ASR / 批量产品化属大步骤二。

隐藏演示：「我的」**连点叶芽 Logo 五次**，可切换角色、示范场景、待确认超声、空状态等。

## 5. 分模块产品内容

### 5.1 此刻 `(tabs)/now`

| 项 | 说明 |
|---|---|
| 用途 | 回答：我在第几周/哪一阶段？下一件要紧事？带什么？ |
| 关键交互 | 孕周卡可 ∨/∧ 展开细节；下一步默认 2 条；主 CTA 按情境为「详情 / 携带 / 设提醒 / 完成」；非「完成」时另有轻链完成；「痕迹与携带」折叠 |
| 演示数据要点 | 孕期示范约孕中后期；下一步含参考糖耐、已预约大排畸、复查血常规；携带清单含既往报告与证件 |

页脚固定提示：`参考日程，以医生安排为准`。

### 5.2 档案 `(tabs)/timeline`

| 项 | 说明 |
|---|---|
| 用途 | 家庭事件时间轴；临床报告优先于碎监测排序 |
| 关键交互 | 「收下报告」；折叠「筛选与小结」（主体 Chip + 阶段小结入口）；点事件进详情 |
| 演示数据要点 | 脱敏虚构：示例市妇幼、超声（含胎盘 II 级白话）、NT、血常规、体重血压等 |

列表当前偏「类型 + 时间 + 标题」轻密度；医院 / 多指标主要在事件详情。

### 5.3 健康 `(tabs)/health`

| 项 | 说明 |
|---|---|
| 用途 | 同一份档案数据的趋势视图，不重复建库 |
| 关键交互 | 妈妈 / 胎儿（或宝宝）切换；MetricStrip + sparkline；点进历史；已出生场景可见疫苗列表 |
| 演示数据要点 | 胎心多点、体重 / 血压序列；趋势短句为「较上次接近 / 略高 / 略低」（非诊断） |

引导文案：`报告里的数字，会在这里慢慢连成线`。

### 5.4 我的 `(tabs)/me`

| 项 | 说明 |
|---|---|
| 用途 | 家庭与信任入口；演示后门 |
| 关键交互 | 完善档案、家庭成员、隐私与信任；连点 Logo 开演示；退出登录 |
| 文案 | 「这份档案，只属于你们一家」；AI 说明需确认后进档案 |

### 5.5 报告确认 `report/review`

| 项 | 说明 |
|---|---|
| 用途 | 诊后「先懂再核」：白话 → 指标 → 字段 → 建议 → 确认 |
| 关键交互 | 「芽纪帮读」芯片；出处去重展示；字段 ∨ 展开；测量项总开关「一并记入健康趋势」；建议「采纳 / 全部采纳」；吸底「确认归档」；成功页温暖反馈 |
| Mock 样本 | 超声（胎盘 II 级安抚）、检验、未知类型通用补录 |

免责：`AI 整理结果仅供记录，请以原始报告和医生意见为准。`

### 5.6 提醒与系统日历 `reminder/new`

见第 7 节。提醒类型：产检 / 产后复查 / 宝宝体检 / 用药 / 疫苗。保存后出现在「此刻 → 下一步」。

### 5.7 携带清单

在「此刻 → 痕迹与携带」中勾选；报告确认可开关「加入下次就诊携带清单」。节点材料清单在规格中为知识库能力，本版以示范携带项呈现。

### 5.8 阶段小结 `summary/stage`

基于已确认档案的 Mock 汇总：家人简版 + 可展开的时间线 / 指标 / 医院结论原文 / 叮嘱与未闭环。  
固定免责：小结不构成医学结论。

### 5.9 其他可点页面（原型深度不一）

| 路由 | 说明 |
|---|---|
| `onboarding` | 三阶段极简建档：备孕 / 怀孕中 / 宝宝已出生 |
| `voice/recording` | 一键录医嘱 → Mock 转写与要素确认 |
| `import/batch` | 存量批量导入列表粗确认 |
| `note/quick` 等 | 记叮嘱 / 用药 / 监测 |
| `event/[id]` | 事件详情 |
| `family` / `trust` / `privacy` | 家庭权限收敛（可查看/可编辑）、信任三条底线、隐私 |
| `demo-states` | 状态演示入口（加载/空/失败等，视导航可达性） |

## 6. AI / OCR 能力（本版如何体现）

| 能力 | 本版实现方式 | 用户感知 |
|---|---|---|
| OCR | `createMockReport` + 处理中动画，无真实云 OCR | 上传后进入待确认 |
| 白话解读 | Fixture 预置条目（最多约 3 条）+ 出处 | 「芽纪帮读 · 需你确认」 |
| 建议下一步 | 仅提醒 / 携带 / 记下叮嘱三类意向；需采纳 + 确认归档 | 不是开放式聊天 |
| 低置信度 | 字段置信度阈值约 0.85，可「标记已核对」 | 强制人工门槛 |
| 录音 ASR | 客户端 Mock 倒计时与抽取行 | 确认后才改档案 |
| 阶段小结 | `generateStageSummary` 内存生成 | 事实汇总，非新结论 |

**明确不是**：开放式健康问答、用药推荐、是否该做某项检查的判定、医生好坏评判。

生产形态（规格）：服务端 `OcrProvider` / `LlmProvider` / `AsrProvider` + 自建知识库出处；本版用 Mock 保证无密钥可演示。

## 7. 提醒与系统日历

| 环境 | 行为 |
|---|---|
| iOS / Android 真机 | `expo-calendar`（legacy API）申请权限后写入默认可写日历；备注附「以医嘱为准…」；提前提醒约 60 分钟 |
| Web / 无原生日历 | **不假称已同步**；提示「已保存在芽纪内；真机可同步」；`calendarSync` 记为 `local_only` |
| 权限拒绝 | 提醒仍存芽纪内，状态 `denied` |

配置：`apps/mobile/app.json` 中 `expo-calendar` 权限文案已声明。  
实现：`apps/mobile/src/services/deviceCalendar.ts`。

## 8. 品牌与体验原则（当前实现程度）

### 8.1 视觉（`constants/theme.ts`）

- **马卡龙暖意**：薄荷绿 `#7EB8A8` + 蜜桃强调 + 奶油雾底 `#FDF7F2`
- **叶芽**：`SproutMark` / `BrandMark`，登录与「此刻」「我的」品牌记忆点
- Web 字体倾向 Nunito + 中文系统黑体；数值 tabular-nums
- 气质目标：安静的家庭档案工具（偏系统「健康」克制），非运营型母婴 App

### 8.2 文案温度（`WARM_COPY` 摘录）

- 登录：`把每一次看诊，收成家里能翻开的故事`
- 此刻：`慢慢来，先看清下一件要紧事就好`
- 归档成功：`好了，已经收进家里的档案`
- AI：`AI 帮读 · 需你确认`

### 8.3 UX 迭代取向（对照 2026-08-08 R1–R3）

已明显落地的方向：

- 「此刻」折叠降噪；「收下报告」统一命名  
- 报告白话置顶 + 字段折叠 + 吸底确认  
- 档案临床优先排序；健康默认胎儿 / 胎心  
- 底栏几何图标；∨∧ 折叠语言逐步统一  
- R3「五刀」方向在代码中的对应：未闭环副文案去重、下一步情境 CTA、出处去重、建议全部采纳、趋势中性措辞（略高/略低）、确认页吸底等  

R3 仍指出的差距（未宣称已全部解决）：档案叙事密度、健康「线」的可信度、同屏折叠次数、登录宽屏布局等——属后续精修，不是本版验收已过双高线。

## 10. 如何本地运行与演示

### 10.1 仅跑移动端原型（最常用）

```bash
pnpm install
pnpm --filter @yaji/mobile start
# 或：pnpm dev:mobile
```

- Expo 开发服默认端口常见为 **8081**；若占用会自动递增（UX 走查记录里出现过 8082）。  
- 可选：`w` 开 Web，或扫码真机。  
- **硬刷新 Web 会清空内存示范数据**；底栏切换可保留当前会话态。

### 10.2 示范入口

| 入口 | 操作 |
|---|---|
| 登录页 | 「体验示范档案」→ 孕期示范 / 已出生示范 |
| 登录页 | 「填入演示号」→ 虚构号 + 验证码 → 建档 |
| 我的 | 连点 Logo **五次** → 角色 / 场景 / 待确认超声 / 空状态 |

推荐主路径：孕期示范 → 此刻 → 收下报告 → 确认归档 → 健康看趋势 →（可选）阶段小结 / 设提醒。

### 10.3 完整后端（大步骤二目标，非本版演示必需）

```bash
docker compose -f infra/docker-compose.yml up -d
cp .env.example .env
pnpm prisma:migrate
pnpm prisma:seed
pnpm dev
```

## 附录 A · 与执行规格的已知偏差（诚实标注）

3. **追踪矩阵**（`docs/traceability-matrix.md`）部分编号仍偏早期页面表（P01–P17），与 v2.0 新增 VOICE / SUMMARY / NOW 日历等条目的同步以执行规格与 PROJECT_PLAN 功能包表为准。
